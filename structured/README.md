# Structured Data

`structured/` 保存可公开提交的课程结构化数据。它是教学生成、图谱同步和公式/表格引用解析的重要输入。

## 当前内容

| 文件类型 | 作用 |
| --- | --- |
| `chapter*.json` | 章节原文、标题、知识点和结构化内容 |
| `formula_library.json` | 公式编号、LaTeX、说明和来源上下文 |
| `table_library.json` | 表格编号、标题和结构化表格内容 |

## 谁会读取这些文件

- 教学 API：生成讲稿、问答、练习题
- 维护 API：把结构化内容同步到知识图谱
- 单端口入口 `render_app.py`：在图谱节点过少时触发自动同步

## 推荐引用格式

```text
[[FORMULA:6.35]]
[[SEE_FORMULA:6.35]]
Equation 6.35
```

后端会尽量从 `formula_library.json` 展开公式内容，再交给前端渲染。

练习题和授课文案会优先使用章节内容与这些结构化引用。公式进入前端后由 Markdown / KaTeX 渲染，因此结构化数据里应保留稳定的 LaTeX 表达，不要把公式手工改成截图或不可解析文本。

## 维护约定

- 只提交确认可公开分发的材料
- 优先保持原始术语和编号稳定，避免破坏现有引用
- 新增字段后，需要同步检查 `education/`、`maintenance/` 和相关前端显示逻辑
- 如果变更会影响图谱同步，优先同时验证维护 API 的 `scan-structured` 流程
- 涉及公式、定理、章节标题的改动，应同时抽查教师生成题目和学生练习页的渲染效果
